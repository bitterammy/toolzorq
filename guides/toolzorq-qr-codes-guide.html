How to Make a QR Code That Actually Scans

A QR code is only useful if someone's phone can read it on the first try. Most scanning failures come down to a handful of avoidable mistakes: a code printed too small, poor contrast, too much text packed in, or a code that was never tested before it went out. This guide explains how to avoid all four, and how to generate a code with TOOLZORQ's free QR Code Generator.

What a QR code really holds

A QR code stores the text you put into it — a link, a phone number, Wi-Fi details, or any short piece of text. When someone scans it, their phone reads that text and acts on it, for example by opening the link. The code does not sit on a server somewhere: the information is in the pattern itself. That has one practical consequence worth knowing before you print anything: if the link inside the code changes later, the old code will still point at the old link. So get the destination right first, and only generate the code once you are sure of it.

Shorter content also scans more reliably. A short link produces a simpler, less dense pattern than a very long address, and a simpler pattern is easier for a camera to read, especially at small sizes or in poor light. If your link is long, shorten it first through whatever short-link option you already use, then put the short version in the code.

Size and print: the rules that prevent failures

Size is the most common cause of unscannable codes. A code printed on a business card, a flyer, or a poster needs to be big enough for a phone held at a normal distance to read it. As a rule of thumb, the further away people will stand when they scan, the bigger the code must be — a code on a poster viewed from a metre away needs to be much larger than one on a card held in the hand. When in doubt, print one copy at full size and test it from the distance people will actually stand at.

Contrast matters just as much. QR codes are designed to be read as dark modules on a light background. A dark code on a white or pale background scans best; light codes on dark backgrounds, or codes printed over busy photographs, frequently fail. Keep the background plain and light, and keep the code itself a single dark colour.

Leave a quiet margin around the code. Scanners need a clear border of empty space around the pattern to recognise where the code starts and ends. Do not crop the code tight, do not let text or logos overlap its edges, and do not place it right against another graphic. A clean margin of white space around all four sides is part of the code, not wasted space.

Rule of thumb: print it, then scan it yourself from the distance your audience will stand at, in the light they will stand in. If your own phone hesitates, theirs will too — make it bigger, simpler, or higher-contrast before you print the rest.

Where QR codes work well — and where they do not

QR codes work best where the person scanning is already looking at the thing carrying the code: a menu on a table, a flyer in someone's hand, a poster at an event, or a product label. They work badly where people are moving fast, where the code is tiny, or where there is no signal to open the link afterwards — a code on a fast-moving vehicle or a roadside board is rarely worth it, and a code whose destination needs the internet will frustrate anyone scanning it offline.

Also consider whether a QR code is needed at all. If the link is short and easy to type, plain text may serve better. A QR code earns its place when the destination is long, hard to type, or needs to be reached without typing — which is exactly the job it does best.

Quick checklist

  • Is the destination final — the exact link, number, or text you want people to reach?
  • Is the content as short as it can be, so the pattern stays simple?
  • Have you scanned the code yourself with an ordinary phone camera?
  • Is the code big enough for the distance people will scan from?
  • Is it dark on a light, plain background, with a clear empty margin around it?
  • Have you tested a printed copy, not just the image on screen?
