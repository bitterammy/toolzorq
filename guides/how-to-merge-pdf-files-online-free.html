Two PDFs that belong together turn up as separate files all the time: a scanned contract in three parts, a CV and a cover letter, a set of invoices for one month, or the chapters of a report saved one by one. Sending them as separate attachments works, but the person at the other end has to open each one, in the right order, and hope nothing goes missing. Merging them into a single PDF is the tidy fix — one file, one attachment, pages in the order you chose.

What does merging PDFs mean?

Merging PDFs means taking two or more PDF files and joining them into one PDF, with every page kept in the order you set. The first file's pages come first, then the second file's pages, and so on. Nothing inside the pages changes: the text, the images and the layout of each page are copied exactly as they are.

That is different from compressing a PDF, which shrinks a file, and from converting a PDF, which changes its format. Merging only changes the container — the pages are the same pages, in a new order, in one file. A merged PDF opens in any PDF reader, prints like any other PDF, and can be emailed, uploaded or archived as a single document.

A few things are worth knowing before you start. Merging does not combine two pages into one page: a ten-page PDF and a five-page PDF become a fifteen-page PDF, not a ten-page one. Different page sizes stay different: if one file is A4 and another is US Letter, the merged file keeps both sizes, page by page. And merging does not make a file smaller — the merged file is roughly the size of all the files added together. If the result is too big to email, compress it afterwards; TOOLZORQ's PDF Compressor shrinks a PDF in the browser the same way, with nothing uploaded.

Why merge in your browser instead of uploading?

Most of the well-known free PDF mergers work the same way: you upload your files to their server, the server joins them, and you download the result. That works, and for ordinary files it is fine. But it has three costs that a browser-based merge does not have.

The first is privacy. A contract, a medical form, an ID scan, a bank statement — these are the very files people merge most often, and uploading them means a copy sits on somebody else's server, even briefly. Most large tools say they delete uploaded files within an hour. But the copy still leaves your device, and you have to trust the deletion promise. With a browser merge, the files never leave your device at all, so there is nothing to delete and nothing to trust.

The second is speed on a slow connection. Uploading a 20 MB scanned PDF on a slow connection takes a while; downloading the merged result takes a while again. A browser merge skips both trips: the file is already on your device, the merge happens there, and only the finished file is downloaded — on most devices that download is instant because it never leaves the machine.

The third is the account wall. Many upload-based tools let you merge a couple of files for free and then ask you to sign up, or limit the file size, or add a watermark. A browser tool has no server cost per merge, so there is nothing to charge for and no reason to ask for an account. Upload-based tools are not bad — they handle very large files better, because a server has more memory than a phone browser, and some offer page-level editing that a simple merger does not. The point is to match the tool to the files: if the documents are private, or the connection is slow, or you simply do not want another account, merge in the browser.

Getting the order right

The order of the files is the order of the pages, and it is the one thing worth checking twice — a merged PDF with the chapters in the wrong order is worse than separate files, because the reader may not notice. The tool shows each file's page count as you add it, which helps in two ways: you can confirm that every file is complete, and you can spot a file that is out of place by its length.

A simple habit prevents most mistakes. Before you merge, name the files in the order they should appear — "01-contract", "02-annex-a", "03-annex-b" — and add them in that order. Then read the list top to bottom once, and check the first and last page of the merged file after it downloads. If a file is in the wrong place, move it with the up and down buttons and merge again; the original files are untouched, so re-merging costs nothing. When the order is by date, put the oldest first; when it is by importance, put the cover letter or summary first and the supporting documents after it.

What happens to your PDFs when they merge?

It helps to know what the merge does and does not do, so the result never surprises you. The merge copies every page of every file, in order, into a new PDF. The text stays selectable where it was selectable, the images stay at the same quality, and each page keeps its own size and orientation. A scanned page stays a scanned image — merging does not turn it back into text, and it does not make it searchable.

Some document-level extras may not carry over. Bookmarks, outlines and some interactive elements — such as form fields and links between pages — are attached to the document rather than to individual pages, and a simple merge does not always preserve them. The pages themselves are fine, but if your original PDF relied on bookmarks to navigate a long document, check the merged file and re-add navigation if you need it. The same applies to digital signatures: a signed PDF that is merged into a new file is no longer the signed original, so keep the signed originals and merge copies only for reading or filing. Page numbers are another small trap: if each original file numbered its own pages from one, the merged file will have several page ones, because the merge does not renumber anything.

Common problems and how to fix them

  • A file will not add, or the tool reports an error. The commonest cause is a password-protected PDF. A merge tool cannot open a file it cannot read, and a password lock counts as unreadable. Remove the password from a copy of the file first — in your PDF reader, or with the tool that created it — and then merge the unlocked copy. Keep the protected original.
  • A file looks damaged or will not open at all. Re-download it or re-export it from the app that made it. A PDF that your reader cannot open will not merge either, and the tool will tell you which file is the problem.
  • The merged file is too big to email. Merging adds sizes together, so three 8 MB scans become a 24 MB file — too big for many email attachments. Compress the merged file afterwards with TOOLZORQ's PDF Compressor, or split the merge into two smaller files.
  • The merge is slow. Very large files, especially scanned image-heavy ones, take longer because the work happens on your device. Close other heavy browser tabs, and merge on a computer rather than a phone if you have a choice.
  • Pages come out in the wrong order. The list order is the page order, so check the list before you press Merge PDFs. Move files with the up and down buttons, and check the first and last page of the result. Re-merging is free and the originals are untouched.
  • The merged file opens but looks wrong. Check the originals first: a page that was rotated or upside down in the original stays that way in the merge. Fix the rotation in the original file, then merge again.

Other ways to merge PDFs

The browser tool is the quickest route for most people, but it is not the only one. Which method fits depends on your device, the size of the files, and whether you want extra editing as well as merging.

On a Mac: Preview

Every Mac already has a PDF merger built in — Preview, the app that opens PDFs by default. Open the first PDF in Preview, show the thumbnails sidebar, and drag the other PDF files into the sidebar at the position where you want them. Then choose File, then Export as PDF, and save the merged file. It is free, it works offline, and nothing is uploaded. The drawback is that it is manual: for ten files it is ten drags, and there is no batch step.

On Windows: PDFsam Basic

PDFsam Basic is a free, open-source desktop app for Windows, Mac and Linux, made for merging, splitting and rotating PDFs. Download it once, add your files, set the order, and merge. It works offline, it handles large files well because it runs on your computer, and it has no upload step. The cost is the download and install, and the occasional prompt to upgrade to the paid version, which you can ignore.

On Linux: the command line

If you are comfortable with a terminal, two small commands merge PDFs in one line. With PDFtk: pdftk file1.pdf file2.pdf cat output merged.pdf. With Poppler's pdfunite: pdfunite file1.pdf file2.pdf merged.pdf. Both are free and fast — the best option for repeated merges, and the worst if you never use a terminal.

Online: Adobe, iLovePDF and Smallpdf

Adobe's free online merger, iLovePDF and Smallpdf all merge PDFs in the browser window, but the work happens on their servers: you upload the files, the server joins them, and you download the result. They are polished, they handle large files, and they offer extra tools — splitting, rotating, reordering individual pages — that a simple merger does not. The trade-offs are the upload itself, the free-tier limits, and the account prompts. For sensitive documents, or when you simply want the job done without an account, a browser merge is the simpler choice.

After merging: compressing, sharing and filing

A merged PDF is often bigger than any single original, so the next step is usually to shrink it. If the merged file is too big to attach to an email — most email services cap attachments around 20 to 25 MB — run it through TOOLZORQ's PDF Compressor before sending. The compressor renders each page to a smaller image and rebuilds the PDF from those images, so the file gets much smaller, especially for scanned PDFs. The trade-off is that the pages become images, so the text is no longer selectable or searchable — keep the merged original if you need the text.

For filing, one merged file per case, month or project keeps a folder tidy — "invoices-2026-03.pdf" is easier to find than twelve separate scans. And for archiving, a merged file plus the originals is the safe combination: the merged file is the readable copy, the originals are the evidence.
